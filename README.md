# 🎓 英语六级词汇刷题系统

一个面向日常复习的 **CET-6 词汇刷题系统**。词库严格取自两本刘晓艳纸质教辅书（大纲词汇 6,363 词 + 核心词汇 3,324 词），按书中 Unit 顺序、词群结构与艾宾浩斯打卡表排程复习，支持 PWA 安装到手机/电脑，像原生 App 一样全屏使用。

**🔗 开始刷题（推荐）**：https://adrian0314.github.io/cet6-cihui-shuati/cet6_quiz.html
手机浏览器打开 → 菜单/分享 →「添加到主屏幕」，即可全屏使用。

**为什么值得用**

- 📖 **详解全覆盖** —— 6,363 + 3,324 条词条的「🧠 巧记 + 💬 例句」覆盖率均达 100%，另附派生词、易混淆词辨析与词群导图
- 🎤 **跟读练习** —— 听标准发音、检测目标词匹配、录音回放与自评，练习记录自动保存
- 🎯 **严格贴教材** —— 词库与复习排程都照抄纸质书，Unit 1-14 打卡表逐日逐项一致，不是拼凑词表
- 💾 **数据自主** —— 统计、错题、学习进度全存本地，支持导出备份 / 导入恢复 / 恢复出厂

## 🚀 快速开始

### 方式一：手机 / 浏览器直接使用

手机上点击这个链接 **https://adrian0314.github.io/cet6-cihui-shuati/cet6_quiz.html**，用浏览器打开，点击右上角三个点，点击 **「添加到主屏幕」** 即可在桌面快速点击使用（全屏运行）。

### 方式二：安装为 App（PWA）

1. 部署到任意静态托管（GitHub Pages / Netlify / Vercel）
2. 用手机浏览器打开链接：
   - **安卓**：Chrome/Edge → 菜单 →「添加到主屏幕」
   - **iPhone**：Safari → 分享 →「添加到主屏幕」
3. 安装后全屏运行，数据保存在当前浏览器

> 注意：PWA 安装需通过 https 地址访问，本地双击打开不支持安装。

### 方式三：打开下载的页面文件

进入仓库目录，双击 `cet6_quiz.html` 可浏览词库和做题。发音检测需要通过 HTTPS 网页或本机 HTTP 服务打开，不能使用 `file://`。

### 方式四：词群导图查看器（只看导图）

不想做题、只想浏览词群导图时使用——Unit 1-10 全部词群整树展示，不用一个一个点节点：

- **在线版**：https://adrian0314.github.io/cet6-cihui-shuati/word-maps-viewer.html
- **单文件版**：双击 `word-maps-viewer-offline.html`（数据已内联，单文件可拷到 U 盘/手机/别的电脑，无需网络）
- **文件版**：双击 `word-maps-viewer.html`（需与 `unit-maps.js`、`core-words.js` 同放一个目录）
- 功能：Unit/词群下拉切换、🔍 搜索单词自动定位并高亮、点卡片朗读发音、点 ○ 折叠/展开分支、滚轮/双指缩放、拖拽平移、⬇ 导出 SVG/PNG；「◀ 上一个 / 下一个 ▶」导航条固定在底部图例上方独立成行，每次加载新词群初始视野自动以根节点为中心

> 词库/导图数据更新后，在仓库根目录运行 `node build-core-words.js`，再运行 `node build-offline-viewer.js`，可同步词库索引并重新生成单文件版。

### 方式五：词群编辑器（维护工具）

仓库附带词群导图编辑工具链，需本机安装 [Node.js](https://nodejs.org/)（建议 18+）：

1. 在仓库目录双击 **`打开词群编辑器.bat`**：自动检测词典服务端口（17989），未运行则拉起 `node dict-server.js`，随后在浏览器打开 `word-map-editor.html`
2. 编辑器支持：从有道词典抓取单词讲解（服务未启动时尝试直连）、可视化编辑词群导图节点、保存回 `unit-maps.js`
3. 也可单独双击 `启动词典服务.bat` 只启动服务；改完导图重新发布即可更新网站的词群导图

> 说明：`dict-server.js` 仅用 Node 内置模块（http/https/fs），无 npm 依赖；词典数据来自有道公开接口。

|---|---|
| 🏰 闯关模式 | 严格对应书中使用指南：闯关1「词群速记」（认识/不认识快刷）、闯关2「选择检测」（Lesson 检测，选择题/默写题）、闯关3「Unit 综合测」（覆盖整个 Unit） |
| 🧠 记忆模式 | 做完一题即从队列移除，答错的词按间隔自动排期回来复习 |

| 🎯 三种题型 | 看中文选英文 / 看英文选中文 / 默写（智能近似判定） |
| ✍️ 手写默写 | 手写板识别单词，结合词典自动纠错 |
| ❌ 错题本 & 重做 | 自动记录错题，支持搜索、按模式重做、答对自动移除 |
| 📖 单词详解 | 答完即学，单词浏览器点「查询」也能看：**🧠 巧记**（构词 / 联想 / 谐音 / 对照 / 提示）→ **💬 例句**（英文句 + 空格 + 中文译文，两行显示）→ **🌱 派生词**（同族词 + 音标，可朗读）。**全部词条已配齐巧记与例句**：核心词汇 3324 词、大纲词汇 6363 词覆盖率均达 100%（含书中 * 标注的派生词） |
| 🔎 单词浏览器 | 「词库」标签按单元检索全部单词：默认 **大纲词汇 Unit 1-14（6363 词）**，可切换 **核心词汇 Unit 1-10（3324 词）**；单元按钮逐个筛选，搜索支持中英文；每词可查询详解、查看词群导图、朗读发音、标记重点词 |
| ⭐ 重点词 | 做题时在单词标题/音标旁点击「☆ 标记重点」或「★ 已标记」添加/取消当前单词；状态同步到重点词列表和智能练习 |

| 📊 详细统计 | 正确率、连对、每日热力图、近7天趋势、题型对比、词汇掌握情况、每日目标达标庆祝 |
| 📌 单元筛选 | 手动切换 Unit（大纲词汇 Unit 1-14 / 核心词汇 Unit 1-10）或全部单元；做题队列为当前筛选范围内的全部单词 |

| 🎤 发音练习 | 标准发音、目标词匹配检测、录音回放、自评与练习记录 |

## 📖 使用指南

### 开始做题

做题页从上到下依次设置：**词库 → 单元筛选 → 闯关模式 → 做题模式 → 题目类型 →（可选）记忆模式 / 自动朗读**，然后点「▶ 开始做题」。

- **做题模式**：看中文→选英文 / 看英文→选中文
- **题目类型**：选择题（四选一，遇到已知缺失释义的词条会自动修复显示，例如 `animal` 会显示“动物”）/ 默写题（键盘输入或手写板）
- **重点词**：做题时在单词标题与音标右侧点击「☆ 标记重点」或「★ 已标记」添加/取消当前单词；切换题目后按钮会跟随当前单词并保留状态，状态也会同步到重点词列表和智能练习
- **做题进度与定位**：做题时直接显示整轮答题进度，顶部进度条中绿色表示已完成，灰色表示未完成，青绿色高亮表示当前题；切换上一题、下一题或输入题号跳转时会自动滚动跟随当前题，当前题固定显示在进度条中间（首尾题也居中）。非全屏翻题时，题卡会定位到吸顶导航栏下方，避免手机端导航遮住题面首行或全屏按钮
- **中途退出**：做题进行中会即时把当前题位、已答数量和已选答案写入本地存储；手机切到后台、刷新页面或关闭网页时，页面生命周期事件还会再次保存，重新打开后点击顶部「继续做题」即可接着完成同一队列。手机从其他应用返回后，恢复保护会忽略浏览器补发的旧「不会，跳过」事件：首次真实点击选项可正常作答，只有实际按下跳过按钮才会执行跳过；跳过点击还必须落在真实起手之后 1.5 秒内，且起手必须发生在切回前台之后，补发的旧触摸（含完整序列重放）会被整事件取消，切后台很久再回来时点击选项不会被误判为跳过，跳过按钮也不会无故闪动。4 周 25 天计划会同时保存当日进度，复习提醒也会显示实际的已完成题数和待完成题数；当天新 Unit 的全部单词学完后会记录为已完成，不会再生成同一 Unit 的整组复习；复习队列中断后重新开始时只推送当天尚未答过的词，已练过的题不会重复出现；进入新的一天后，前一天**已完成**的任务按作答记录补判并正常推进到下一天，而前一天**未完成**的任务会被清空进度并强制整份重做，当天不能改做原定当天的计划；已答完但来不及清除的旧队列也会在重进时自动丢弃。
- **朗读发音**：点击单词旁的喇叭按钮优先使用普通媒体音频，以便跟随视频/音乐的蓝牙输出；网络音频无法播放时自动回退到系统 TTS，网络不可用时仍可使用系统 TTS
- **自动朗读**：在练习设置中切换「自动朗读：开/关」，开关会保存到本机；开启后仅在“看英文 → 选中文”时，每显示一道新题朗读一次，不会因答题反馈或局部刷新重复朗读。若浏览器限制非用户操作播放，可使用题面旁的朗读按钮
- **答题后信息顺序**：提交答案或跳过后，题目与正确答案下方紧接默认展开的“📖 单词详解”（巧记、例句、派生词）；随后显示“⚠️ 易混淆词”辨析和词群归属信息，最后显示“🗺️ 词群导图”。点击标题可收起或重新展开单词详解内容。

### 🏰 闯关模式

| 关卡 | 名称 | 用法 | 适用场景 |
|---|---|---|---|
| 闯关1 | 词群速记 | 认识/不认识二选一快刷：**认识**直接进入下一词，**不认识**先展示默认展开的单词详解，再显示词群导图。快捷键 `1`/`空格`=认识，`2`=不认识 | 首次接触新词群，快速过一遍混个脸熟 |
| 闯关2 | 选择检测 | 标准四选一 / 默写题，答完即显示详解 | 学完一个 Lesson 后的检测 |
| 闯关3 | Unit 综合测 | 一次覆盖整个选中 Unit 的全部词 | 学完一个 Unit 后的综合检测 |

**取题量**：每个闯关的做题队列都是当前筛选范围内的全部单词（闯关1/2 按书中顺序，重做模式为全部错题乱序）。做题中切换闯关模式会先保存当前进度。

### 🗺️ 词群导图

答完题自动显示当前词的词群关系图（单词浏览器点「🗺️ 导图」按钮也可查看）——中心=词群主题或当前词，四周圆圈=关联词：

- **分支徽标**：圆圈外侧的绿色数字徽标表示该词下面还有几个分支；点击带徽标的圆圈逐层展开，没有徽标的圆圈=末端词（无分支），点击朗读发音
- **连线颜色**：绿=派生（扩/合成）、蓝=同根、橙=近义、红=反义、粉=形近、灰=相关，虚线=形近/反义
- **覆盖范围**：大纲词汇 Unit 1-10（书页真实导图）；导图未覆盖的词自动回退旧版导图

### 🧠 记忆模式

点「🧠 记忆模式」按钮开启，做题时**做完一题即从队列移除**，答错的词按当前词库的书中记忆规律自动排期回来复习：

- 每次进入记忆模式的队列 = **到期复习词** + 当前选中范围内的**未学新词**
- 做完一题即删，不回头重复；答错词进入记忆调度，到期自动回来

**记忆规律：**
- 大纲词汇 → 「4周25天计划」（Unit 1-14 全部参与）：第 1-14 天每天新学一个 Unit，之后按 **+1天/+3天/+6天/+11天** 间隔复习，第 15-25 天只做复习（如第9天学 Unit 9 并复习 Unit 3、6、8；第14天学 Unit 14 并复习 Unit 3、8、11、13；第25天复习 Unit 14 收尾）。每日 Unit 顺序逐日照抄纸质打卡表，见下方「📅 4周25天计划」完整表
- 核心词汇 → 书中每词 8 格周期：**5分/30分/12时/1天/2天/4天/7天**

**到期复习：**
- 打开网页时若有到期单词，做题页顶部显示绿色**复习横幅**，点「开始复习」四选一快刷一键清债，跳过视同答错
- 5分/30分 这类短周期在学习会话内实时提醒
- 4 周 25 天计划的完成判定以**实际作答**为准：当前计划日的每个 Unit 全部单词都答过一遍（不限做题入口），计划栏即显示「当天目标已完成」

跟读面板统一为「听标准发音 → 录音 → 目标词匹配 → 回听 / 自评」流程，无需切换模式或填写服务连接信息。

### 录音对比第三轮：加本地人声检测（VAD），修掉"能听到自己却检测不到"

**现象**：用户反馈"录音对比里我能听到自己的声音，但系统仍然无法识别到"。

**根因（两个问题叠加）**：
1. **功能语义**：`录音对比` 当时只有「录制 → 回放」，**没有任何检测逻辑**；
2. **提示串台**：面板上那句「已结束跟读，没有识别到内容」是**上一次点「开始跟读」**留下的，未随录音更新，
   看起来就像"录音里检测不到人声"。

**顺带发现并修掉的三个真实技术缺陷**：
- **解码不可靠**：`decodeAudioData` 解 `MediaRecorder` 的 webm/opus 实测**只解出 0.06 秒**（文件 >1 秒且能正常回放），
  以此做分析必然误报"没声音"→ 改为**录音期间实时采集 20ms 音量包络**（`AnalyserNode`），解码仅作兜底；
- **VAD 阈值取法错误**：原来以"整体均值×2"为噪声底，说话占比高时阈值被顶到人声之上 →
  改用**低分位（20%）估噪声底**，阈值 `max(噪声底×3, 峰值×8%, 0.004)`，并加 0.6 倍迟滞；
- **状态行串台**：录音对比改用**独立状态行** `#ppRecStatus`，与跟读互不覆盖。

**现在的结论文案**：✅「已检测到人声：约 x.x 秒，峰值 xx%，约 n 个音节段」（音量偏小会额外提示）；
❌「未检测到清晰人声：录音里几乎只有底噪…」并给出靠近麦克风 / 调大音量 / 蓝牙改内置麦克风的建议；
并明确标注"本功能做本地人声检测，不做云端识别"。

**验证**：`test_pron_practice_regression.py` 扩到 **15 项**（新增⑭ VAD 纯函数三态判定——
静音/人声/轻声，并断言"阈值不得高于峰值一半"以锁死历史缺陷；⑮ 端到端真实假设备录音判为已检测到人声）；
全量 **126 项测试通过**；sw.js v35 → v36；排查指南更新第三轮（根因 + 三个技术缺陷 + 一句话排查口径）。

### 发音练习第二轮：区分"收不到声音"与"收不到识别结果"＋三条独立通道

**背景**：用户反馈"耳机设置正常，浏览器仍收不到声音"。两张截图给出关键证据——
自检电平曾显示 **100%**（设备其实在送声音），随后却又提示"没有输入"。
排查发现两个真实缺陷，以及一个更常见的环境事实。

**缺陷一：静音判定用了瞬时值**。原判断只看"判定那一刻"的电平，于是**先说后停**会被误报成
"一直没有声音输入"。→ 改为按整段**最大电平**判断，并区分"设备有声音 / 没有声音"两种结论去向。

**缺陷二：自检与识别抢麦克风**。电平表持有 `MediaStream` 的同时又启动语音识别，
蓝牙耳机（HFP）与单麦克风设备**同时只能被一路抓取**，很容易两边都拿不到干净音频。
→ 检测/录音结束即释放，并**在开始识别前主动释放**（`ppReleaseMic()`），
新增回归测试 ⑫ 锁定"跟读期间不得继续持有麦克风流"。

**环境事实：识别结果与麦克风是两件事**。Chrome/Edge 的网页语音识别是**云端服务**，
网络受限时会只"听"不返回；Firefox 不实现该 API；Safari 走自有通道。
因此新增两条**独立运行**的替代通道：
- 「🎚 检测麦克风」：只开麦看实时电平（6 秒），并给出结论——"有声音输入（设备与权限正常，
  识别失败多半是识别服务/网络问题）"或静音提示；
- 「⏺ 录音对比」：`MediaRecorder` 录下自己的朗读（最长 6 秒）并**本地回放**，配合标准发音与自评按钮，
  不依赖任何云端服务。

**还新增**：面板内**输入设备下拉框**（≥2 个设备时出现；选择记在本机；
`deviceId` 失效时自动清选择并回退系统默认，对应 `OverconstrainedError`/`NotFoundError`）。

**验证**：`test_pron_practice_regression.py` 扩到 **13 项**（新增：真实假设备下电平读数与释放、
跟读期间已释放麦克风、录音对比生成可回放地址；并适配"开始跟读前约 1 秒麦克风探测"的时序）；
全量 **124 项测试通过**；sw.js v34 → v35；排查指南更新为第二轮（含输出设备对录音的影响、
页面内输入源选择、驱动与占用、跨浏览器差异、逐步验证清单）。

### 发音练习增强：麦克风自检（实时输入电平）+ 具体错误提示

**背景**：用户反馈「耳机能听声音，但网页录音收不到麦克风」——站点只回了一句"没有识别到内容"，
无法区分是**环境问题**（设备/权限）还是**功能问题**。排查确认其后来自系统侧：
Windows「设置 → 系统 → 声音 → 输入」把蓝牙耳机的「允许应用和 Windows 将此设备用于音频」设为了**不允许**，
而它同时是默认输入设备，于是任何应用都收不到声音（详见 `浏览器录音-麦克风排查指南-20261006.md`）。

**站点改动**：
- 面板新增 **「输入电平」实时自检条**：开始跟读时用 `getUserMedia` 取流 + `AudioContext/AnalyserNode`
  画实时电平；说话时条会动，不动就说明声音没进来（一眼区分环境问题与功能问题）；
- **错误分类提示**：把 `NotAllowedError / SecurityError`、`NotFoundError`、`NotReadableError`、
  `OverconstrainedError` 等翻译成可执行的中文提示（改哪里的权限、检查哪个设备）；
- **不阻断识别**：麦克风检查失败只提示原因，仍然尝试一次语音识别（权限刚放开时仍有成功机会）；
- **静音告警**：2.5 秒内电平始终为 0 → 明确提示"麦克风一直没有声音输入"，并列出三处必查设置
  （系统默认输入设备、设备属性里的"用于音频"开关、蓝牙耳机是否处于免手操/通话模式）；
- **超时兜底**：`getUserMedia` 1.5 秒不返回（设备弹窗挂起）时继续进入跟读，按钮不会像"没反应"；
- 结束时统一释放麦克风：停 `requestAnimationFrame`、关 `AudioContext`、`stop()` 所有 `MediaStreamTrack`。

**验证**：`test_pron_practice_regression.py` 扩到 11 项（新增：权限被拒给出具体提示且不阻断识别、
麦克风检查挂起不卡住跟读、真实假设备下电平表能读到声音且静音提示文案覆盖三处必查项）；
全量 **122 项测试通过**；sw.js v33 → v34。

### 修复：「结束跟读」点了没反应（发音练习停止路径缺状态机）

- **现象**（用户截图）：跟读进行中按钮显示「⏹ 结束跟读」、状态是「正在听…请朗读 void」，
  点这个按钮后**界面毫无变化**，再点也没反应。
- **根本原因（两条，均已复现）**：
  1. **停止路径没有自己的界面更新**：`ppListen()` 在 listening 分支只调 `rec.stop()` 就 `return`，
     按钮文案与状态文案全部依赖浏览器的 `onend`/`onresult` 回调。
     一旦识别器不回调（麦克风权限弹窗挂起、识别服务无响应），界面就永远停在「正在听…」——
     点按钮"没反应"正是这个卡死状态。
  2. **状态标记与识别器生命周期脱钩**：`listening` 只在 `onend`/`onerror` 里被置回 `false`，
     `onresult`（结果已出）里没有；`stop()` 后也不清 `_ppState.rec`。
     于是「只给 onresult 不给 onend」的实现会让界面同时显示「✅ 发音正确」和「⏹ 结束跟读」，
     此后每次点击都去打一个已结束的识别器 → 永久无反应。
- **修复方案**：
  - 新增跟读状态机标记 `gotResult` / `stoppedByUser` 与看门狗 `watchdog`，由本页自己维护；
  - 新增 `ppStopListening(userInitiated)`：**先立即把界面切到"已结束跟读，正在分析刚才的朗读…"**
    （按钮→「🎤 再读一次」），再调 `stop()` 通知识别器；并设 **1.2s 看门狗**——
    浏览器不给结果就自行 `abort()` 收尾并提示「没有识别到内容，请再试一次」，界面不会再卡死；
  - `onresult` 里**立即**复位 `listening` 并取消看门狗（结果一到界面就恢复正常）；
    `onend`/`onerror` 统一走 `ppListenIdle()` 复位并清理实例；`ppFinish()` 也复位，
    不再出现「结果已出但按钮仍显示结束跟读」的假状态；
  - 开始新一轮前先 `abort()` 上一实例，避免 `InvalidStateError` 与旧回调串轮；
  - 关闭面板 / 点「读对了（自评）」/「再练一次」时，都先按"用户主动结束"收尾。
- **时序验证**（真机形态：`stop()` 后 60ms 才返回结果）：点「结束跟读」→ 界面立刻复位 →
  60ms 后拿到结果并显示「✅ 发音正确」；挂起形态：立刻复位 → 1.2s 后提示「没有识别到内容」→ 可继续下一轮。
- **回归测试**：`test_pron_practice_regression.py` 新增 2 项——
  ⑦「识别器完全不回调时，点结束也必须立刻生效并可继续下一轮」；
  ⑧「只给 onresult 不给 onend 时不得残留假结束态」。全量 **119 项测试通过**；sw.js v32 → v33。

### 修复：释义被截断（C 选项显示「…等的复」）

- **现象**（用户截图）：`renaissance` 的 C 选项显示「n. 尤指某种艺术形式、音乐形式等的复」，
  句子在半截处停住、括号也没闭合。
- **根因**：词库早期按「释义 ≤20 字」的渲染规范裁剪释义时，是**按字符数硬切**的，
  个别词条正好被切在词的中间——`renaissance` 原文是「(尤指某种艺术形式、音乐形式等的)复兴」，

### 修复记录：2026-09-10 电脑端 ↑/↓ 滚动页面

- **问题**：电脑端做题时按 ↑/↓ 页面不动，尤其全屏模式下完全没反应。
- **原因**：原有实现写死 `window.scrollBy`，但全屏做题时 `<body>` 是 `overflow:hidden`，
  真正滚动的是题卡内部的 `.quiz-scroll`，所以滚的容器根本不是同一个；而且这段逻辑放在
  `if (!quizActive) return;` 之后，词库、错题本等同样很长的标签页完全用不上。
- **修复**：改为**动态解析当前真正能滚动的容器**，按优先级逐层挑选——
  1. 焦点元素最近的可滚动祖先（正在某个列表里操作时优先滚它）；
  2. 全屏题卡内的 `.quiz-scroll`；
  3. 当前标签页里第一个可滚动的区块（如 `#browseList`）；
  4. 文档本身。
  每次滚动约 15% 视口高度（下限 120px），带平滑动画并遵循 `prefers-reduced-motion`；
  只有真的滚动了才 `preventDefault`，无处可滚时交回浏览器原生行为。按键处理提到
  `quizActive` 判断之外，因此各标签页都能用；输入框内、带修饰键的组合、弹层打开时
  都不接管。补发的旧按键（时间戳停留在切走之前）依旧不生效。
- **验证**：`python -X utf8 test_swipe_scroll_navigation_regression.py`（14 项，新增全屏题卡、
  词库列表、输入框豁免、补发旧按键四类覆盖）。

#### 二、重做切题手势与「不会，跳过」逻辑

- **问题**：手机把做题页切到后台、在其他 App 停留一段时间再切回后，点一次选项就会自动跳到下一题，连着四五题都这样；想点「上一题」反而被切到「下一题」。
- **原因**：切后台期间浏览器会把切走前积压的输入事件（常常是完整的 `pointerdown → pointerup → click` 序列）在回到前台时一次性补发。旧实现用 80ms / 300ms / 1.5s 多个时间窗口与"延迟一拍"互相打补丁去猜哪些事件是补发的，既漏掉一部分补发，又误伤真实操作——回上一题被冷却期吞掉、连点被当成"风暴"压制，于是"想回上一题却被切到下一题"。
- **修复**：改为**统一手势闸门**，规则收敛为四条：
  1. 起手（`pointerdown`/`touchstart`/`mousedown`）的时间戳必须晚于最近一次切到后台的时刻，切走前的补发事件在捕获阶段整批取消；
  2. 收尾事件必须落在当前手势里且时间戳不倒流——凭空出现的裸 `click` 一律不执行动作；
  3. 一个手势只属于一个起手目标：点选项的手势永远不可能触发「下一题」或「不会，跳过」；
  4. 真机触摸、回到前台后的保护窗口、以及切过后台时手机上的鼠标兼容序列，都要求"起手→收尾"有真实人手耗时（补发批次会被压成 ≈0ms）。
  闸门内不再有延迟执行和冷却期，所以真人操作一次就是一，既不吞掉也不重复。键盘激活（`detail=0` 且紧跟真实按键）单独放行。
- **验证**：`python -X utf8 test_resume_skip_ghost_regression.py`（18 项，覆盖裸 click、带切走前时间戳的重放、压缩冲刷重放、幽灵「下一题」点击，以及真人点按/长按/键盘等正向路径）与 `python -X utf8 test_swipe_scroll_navigation_regression.py`（14 项，含切后台前后的滑动与按钮切题）。

## 🎤 发音练习

先听标准发音，点击「开始跟读」，读完点击「结束跟读」，查看目标词是否匹配。可通过「播放我的录音」回听，也可使用「读对了（自评）」和「再练一次」。

- 首次练习自动准备约 39 MB 识别资源；资源保存后会复用，也可使用「准备识别资源」或「导入资源…」。
- 录音的实际 PCM 交给 Vosk 识别，同时保留 MediaRecorder 录音供回放；音频在浏览器内处理，不发送至评测服务。
- 检测只判断目标词匹配，不生成音素、重音或专业发音分数；没有识别结果时显示「无法判断」，不计入读对或读错。
- 麦克风拒绝、资源加载失败或识别超时都有明确提示；关闭面板或换词会停止采集，旧结果不会覆盖下一轮。
- 不需要账号、密钥或后端配置。标准发音优先使用媒体音源，不可用时尝试系统语音。

使用与维护说明见 [发音练习使用说明](发音练习使用说明.md)。

开发验证：`npm ci`、`npx playwright install chromium`、`npm test`。回归测试包含真实 Vosk 语音识别、录音回放、资源复用和交互生命周期。
